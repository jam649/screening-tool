## Implemented scope

The connector core implements fixed official Intuit HTTPS code exchange, refresh and revocation, safe bounded request handling, full Customer/Vendor pagination and CDC polling. Full queries include inactive records and validate every page before reconciling missing identities. Customer/Vendor IDs are namespaced. The documented company/individual, alias and address policy preserves the complete vendor object; inactive/deleted identity-only tombstones retain historical party fields. Type-aware matching hash rule v2, frozen CSL fixture outcomes and the design §5.4 unchanged-hash no-write behavior remain intact. Role/phone/raw metadata changes do not manufacture a matching change; source identity and sync health remain independent.

CDC uses five-minute overlap and a poll-start watermark. Missing, malformed, future or stale cursors, the 1,000-object cap and unverifiable completeness fall back to a validated full snapshot. The parser handles the official cumulative last-node `totalCount` and blank no-change node, while malformed or failed pages leave parties, cursor and tasks unchanged. Incremental batches never imply full-book deletion. Actual changed parties produce durable scoped screening tasks and immutable current-hash participation evidence.

Auth/API scope includes separate encrypted sandbox/production app configuration, configured-only public flags, source creation, single-use Admin/session-bound OAuth state, permanent realm binding, connection controls, queued full/incremental sync and serialized disconnect. Revocation reports its actual outcome, including `not_required` when no grant requires revocation. Callback query credentials are excluded from application access logs and referrer output. Signed bounded CloudEvents authenticate raw bytes before parsing; receipt identity includes the CloudEvents `source`/`id` pair plus environment, app and realm. Events enqueue polls and never supply party records.

Coordinator integration shares one fenced source lease across import, sync, OAuth and disconnect. Receipts and queued work commit atomically; equivalent queued follow-ups coalesce, but running work cannot absorb a later receipt. Busy deferred work remains queued for recovery. Only connected sources with encrypted credentials receive persistent schedules, and the Source API reports their actual next run. Default connector registration preserves explicit injected handlers. Fixture transport injection is held in application/session-factory memory and never persisted in operation parameters.

OAuth provenance is frozen by ORM and raw SQL guards, including delete/REPLACE protection. Consumption is a single allowed transition. Logout deletes the live session without deleting the historical OAuth record, and callback authority still requires that exact live session. Unique indexes prevent duplicate bound companies within an environment, including default sandbox identity, and duplicate webhook receipt insertion rolls back its queued work atomically. Existing hit, decision, run, audit and participation immutability protections remain active.

## Rotation and rejected-grant safety

No SQLite writer is held during remote HTTP. Accepted rotating refresh tokens persist before subsequent data requests under the same source lease, fence and exact app/source generation, client, environment and realm checks. Credential maintenance uses a system actor and preserves safe request/operation provenance even if the initiating Admin is offboarded during HTTP. Connected status and current Admin authority are checked again inside the business apply writer; disconnect intent can preserve the accepted rotation while preventing party/cursor writes. The later disconnect uses the latest saved token.

App replacement is blocked while an environment source lease is live. Allowed same-client secret/verifier replacement atomically aligns existing encrypted credential generations. A rejected new OAuth grant is never promoted into a connection. Best-effort revocation failure retains a bounded private encrypted backlog and queues system cleanup. Refresh rotation copies the latest backlog under its writer, including cleanup added during HTTP; cleanup preserves an existing valid connection. Final revocation compares source generation and encrypted credential identity before removing anything. Invalid or expired refresh grants mark reconnect required without altering parties or cursor. Public errors/audits contain safe codes and identifiers, not vendor descriptions or credential values.

## Authorship and independent review

Sol agents implemented the connector core, auth/API and coordinator integration in separate file scopes with shared interface agreement. QBO fixture files are manually authored synthetic responses derived from [verified official contracts](../research/vendor-contracts.md#quickbooks-online), explicitly not live recordings, cassettes or customer data. The original government CSL rows, CSV seed and expected 60 screening outcomes remain unchanged.

An actual first-party `claude-opus-5-5` HIGH-effort independent source-only review ran with tools disabled. Its accepted findings were fixed with focused regressions:

- Same-client app-generation changes atomically rebind existing encrypted source credentials.
- The final revocation writer compares source generation and encrypted credential identity.
- Disconnect cancellation before exchange rejects the grant; cancellation during exchange queues cleanup of the latest accepted grant.
- Rejected post-exchange grants receive best-effort revocation, with failed cleanup privately encrypted and retried as system work without connecting the source.
- Async webhook routes bound body reads and run their database writer through the thread pool.
- Receipt lookups use the literal JSON path that matches the SQLite receipt index.

Integration also found a nested exchange-protector failure path that could retain a callback writer while the inner protector tried to record failure. Rolling back before that inner failure handling preserves the no-writer-during-HTTP rule and avoids deadlock. Raw model exchanges remain ignored local files; no transcript, private runtime data or working credentials are included here or published.
