## Integration details

- Reviewer keyboard F/M/E/J/K/V respects text input focus. Match/Escalate buttons remain disabled until `note.trim()` is nonempty; their empty-note keyboard shortcuts focus the note and send no decision request. The source shortcut opens only the API-provided safe HTTP(S) URL.
- Comparison fields use immutable party/listing snapshots. Names and addresses highlight the engine's recorded matched tokens. Native names align only through recorded Unicode/ASCII evidence; a single native word expanding into multiple ASCII words requires every recorded token to match. No frontend fuzzy scoring or transliteration is introduced.
- Prior decisions retain original actor, note and time, with actual field changes. Suppressed and repeated confirmed/escalated observations display their original decision references and do not invent a new human assessment.
- Parties include explicit unscreened and escalated states, current screening coverage, exact zero-hit runs and collapsed previously cleared observations. Current records remain separate from historical snapshots.
- Overview uses actual counts/full-list coverage, the latest successful fetch timestamp and honest unfinished-run wording. Source/list mutations invalidate the new review, party, run, audit and dashboard caches. Signed score-adjustment labels do not infer field matches from configurable weight signs.
- Admin settings expose the public writable fields, retention disabled by default/minimum five years, advanced scoring and source-list filters. User controls protect the last active Admin. Manual invitations, withdrawal and fragment-only acceptance are operational; fragments are removed before API requests and tokens are kept in memory only.
- Source imports preserve success separately from screening-pending warnings, allow valid header-only full snapshots, show rejection caps and distinguish an uncertain server outcome. The example source label is “Vendor directory”; user-entered labels are unrestricted.
