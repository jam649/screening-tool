# Milestone 2 — CSL pipeline

Built and verified 2026-10-13 (full-list smoke continued after midnight UTC). The app can fetch the official public CSL, retain all published data, show version/fetch health, and create durable work for changed listings. Screening itself is implemented in milestone 3; this milestone retains pending tasks until the screening worker consumes them.

## Built

- Strict official envelope parsing, complete-count/offset validation, size bounds, nonempty list and duplicate source/id rejection, canonical screening-field hashes, safe source links, explicit current source abbreviations, and original raw records.
- Separate `csl_fetches` records for every attempt, including failures and repeated downloads. Listing versions compare the full semantic entry set, excluding volatile export timestamps. The exact raw file SHA-256 is retained on each fetch.
- Atomic added/changed/removed diffs, persistent `list_change` tasks scoped to listing UUIDs, reappearance using the existing listing identity, and system closure/disposition of open hits whose listings are removed. Closure audits use the system actor even when an Admin requested the refresh.
- Immutable `csl_entry_revisions` snapshot every listing in every version. Current entries can change while past versions retain their original fields and raw evidence.
- Admin/session/CSRF-protected `/api/v1/csl/status`, `/versions`, `/refresh`, and `screening-tool csl refresh [--file complete.json]`. CLI and API both use the encrypted optional ITA key, with bulk metadata retained if the sources API is unavailable.
- Durable refresh lease prevents concurrent downloads; interrupted leases recover after ten minutes. A download removing more than 25% of a list of at least twenty entries is rejected to prevent accidental mass removal.
- Alembic revision `32dfcc79a042` preserves populated baseline foreign keys while replacing obsolete uniqueness constraints. Migration transactions are owned by Alembic, permitting SQLite's required parent-table rebuild. The independent security migration chains from this revision. Trusted-host middleware and database encryption-key binding are connected to startup.

## Design deviations and limits

The live government file contains **96 published IDs shared across different source lists**. `csl_id` alone therefore cannot be unique. Listing identity and diffs use **(source_list, csl_id)**, preserving the original published ID, with internal UUIDs remaining the target of hits and suppressions. A focused regression proves removing one source's listing cannot remove another source's listing with the same published ID.

Volatile envelope timestamps can change the raw file hash without changing any entries. Separate raw fetch provenance and semantic versions prevent unnecessary versions or screening tasks. Changed legal remarks/source links create a new historical snapshot/version without falsely treating the unchanged matching-field hash as a screening change.

The synthetic 25-entry 5/5/5 regression is an interim fixture. The canonical frozen 300-entry government sample and planted-party dataset belong to milestone 3. Authenticated ITA sources response shape remains pending a user-owned key; its endpoint and recognized `subscription-key` header were verified without credentials. No live QBO/BC sandbox result is claimed.

## Failure modes to carry forward

A new official source name fails closed until its mapping is verified. A real large list removal also fails closed and needs operator investigation. A refresh failure retains the previous list and records health evidence; it does not silently close matches. Database migrations rebuilding parent tables commit at explicit boundaries, so operators should retain backups before upgrades; foreign keys and audit guards are verified afterward. Durable screening consumers must check that a pending listing still exists and its hash is current, so an older task cannot reopen a hit after that listing was removed or replaced. Source timestamps are provenance, not a guarantee the originating agency published all current restrictions.
