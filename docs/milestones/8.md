## Behavior and architecture

Deterministic matching remains the default. Optional Jev and local Laya use the verified named System One Noul request and an immutable result per eligible pair; they never generate candidates. Missing, failed or invalid responses produce `model_prob=null` and the original deterministic score, with sanitized comparison/run evidence. The engine owns the blend and preserves the deterministic likely-match rail. The default `w_det=1`, `w_model=0` follows the measured [local quality benchmark](../research/laya-validation.md); enabling an adapter can record probabilities without changing ranking. A positive weight requires separate calibration.

One encrypted model configuration owns provider, weights, pinned model identities, local endpoint, write-only keys, audited hosted acknowledgment and public generation. Native Admin controls show saved facts separately from edits, preserve omitted keys, clear explicit replacements from input memory after submission or validation, reject impossible Bearer keys, and require explicit reload after a generation conflict. Reviewer sessions do not query the model settings. Saved-provider tests accept only the saved generation and fixed synthetic identity fields; they report actual probability, model, usage, attempts, elapsed time and safe failure codes without claiming screening completion.

The engine prepares original primitive snapshots, hashes, list version and source labels in a consistent read, then ends the transaction before inference. Every outgoing pair rechecks policy, authority and operation fence in a short read that is released before HTTP. Final apply rechecks them under the writer and reads the latest actual human decisions. A newer human decision can supersede a model call while retaining its historical invocation metadata. Concurrent source/list changes never become the earlier model inputs or hashes. API, durable tasks, scheduler and CLI share this service; historical runs remain immutable and model generation participates in current scoring coverage.

Jev uses the fixed HTTPS endpoint `https://api.typesafe.ai/v1/systemone` and pinned `jev-1.13.0`. Every supplied Jev key requires the exact displayed acknowledgment: “Enabling Jev sends your customer and vendor names and addresses to TypeSafe AI for scoring. Laya keeps all data on this server.” Keys use printable ASCII, including spaces preserved byte-for-byte, with an 8192-character cap. Clearing a key makes the public acknowledgment flag false while retaining its immutable historical audit proof. Hosted account entitlement, billing and real Jev inference remain unverified.

Laya accepts only this host's loopback addresses, localhost or explicit Docker host bridge. LAN/public URLs, URL credentials, queries, fragments, extra paths, redirects and environment proxies are rejected. Transport has one retry owner: at most three attempts inside a 30-second total deadline. Authentication, schema and redirect failures are terminal. Response identity encoding and bounded raw bytes prevent unsafe decompression; duplicate maps, pinned returned identity, finite Noul probability and integer usage are checked. An error clears probability/model/usage so fallback evidence cannot also contain an accepted probability. Request/response bodies, keys and exception text do not enter public failures.

The exact offline Laya tokenizer ships as a reproducible 5,333,263-byte gzip. Original tokenizer SHA-256: `609d8f4c067cd3950f88594c5a802616cea245823836ef5848ee4fc40aab5b6f`; compressed asset SHA-256: `5627c3a702d15bec6fd91771c06a8292ae59423fa6235522a68c63420cb0fddd`. The lightweight tokenizer matched the installed publisher tokenizer on four synthetic sequences, including non-Latin/special-token text, and reproduced the 989-state-token room inside 1024. Ordered trimming removes remarks, street lines, then aliases beyond the actual best matching alternate; oversized essential evidence falls back. Actual local usage must match the prepared sequence count. Hosted estimates remain distinct from response usage. No model weights or runtime download are bundled; original upstream notices and licensing accompany the asset.

`screening-tool export training-pairs --output PATH` exports genuine human false-positive/confirmed-match labels using original Hit snapshots and immutable actor/queue-group authority. It excludes escalations, auto-clears, system removals and unlabeled suppressed repeats. Legitimate fanout retains its recorded group. Purged or missing-authority evidence is counted as unavailable rather than reconstructed. CSV distinguishes training rows from its counts/disclaimer manifest. Fine-tuning remains outside v1. Run PDFs read the frozen model policy, weights and generation rather than mutable current settings.
