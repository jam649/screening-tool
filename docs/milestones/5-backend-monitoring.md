# Milestone 5 scheduler and notification evidence

Implemented after signed milestone 4 checkpoint `07717c6`. This note covers the scheduler/SMTP backend ownership only; the combined Compose/browser/export/retention gate is recorded separately in `5.md` and remains required before milestone completion.

The API, operator commands and schedules share persistent operation attempts and resource leases. Screening scopes share one lease; source import/poll operations share a lease per source. Heartbeats, an OS process-start identity (including Linux boot identity), a runtime owner nonce and monotonic fencing prevent live-owner takeover and allow prompt dead-owner recovery. Business sessions check the actual current fence before every commit, including after cached ORM reads. Recovery retains the interrupted attempt and inserts an audited replacement with frozen original inputs; a demoted or deactivated initiating Admin cannot execute queued work.

APScheduler 3.11.3 uses the same SQLite store with an allowlisted JSON job store. Stored definitions contain fixed operation/source IDs, cron/interval fields and timing controls; no credentials, session objects, customer records or executable pickle. Unchanged schedules preserve their next occurrence across restarts. Jobs coalesce missed occurrences, allow one instance, and use a 24-hour grace period. The configured IANA timezone governs daily times, with the server setting/validated configuration fallback. API sources receive periodic polls; CSV uploads remain manual. Pending screening, operation and outbox recovery jobs are woken after relevant commits. Connector handlers are integration slots for milestones 6/7; an unsupported connector reports a durable failure rather than inventing a network contract.

SMTP configuration validates sender/recipient addresses, header controls, ports, HH:MM times and the public origin. Secrets use encrypted `smtp_credentials`; responses expose configured flags only. Omitted secrets preserve existing values, nonempty replacements update them, and explicit clear removes both credentials. Verified TLS is the default, with anonymous plaintext allowed only for explicit loopback fixtures. Secret values never enter audit payloads, scheduler arguments, response validation errors or transport logs.

Morning reports freeze the queue facts, recipients, sender, MIME bodies and UTC reporting window into encrypted outbox batches. Their plain-text/HTML alternatives include current queue links, likely observations, new hits, slider auto-clear counts, separate removed-list closures, CSL changes, source health and the ITA disclaimer. Empty reports still send. Each recipient has a stable Message-ID and independent delivery state. Successful recipients are not resent; partial retries use the frozen body and original recipient list. `last_report_at` advances to the fixed window end only after every recipient succeeds. Failed messages back off; a disconnected/timeout DATA exchange or abandoned `sending` state becomes uncertain and requires explicit authorized retry. A live delivery worker blocks competing explicit retry.

Every likely observation is included when alerts are enabled, including suppressed observations and repeats retaining prior confirmed/escalated decisions. Their original human actor, note and decision time are labeled. Matching inserts the encrypted batch within its own transaction; SMTP starts only after committed screening/import/refresh work. Invitation messages similarly retain the raw fragment token only inside encrypted outbox content, and invalid/expired/revoked invitations or offboarded issuers are cancelled before dispatch. Manual invitation links remain available.
