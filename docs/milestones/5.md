# Milestone 5 — monitoring, reports, exports and retention

Verified locally on 2026-10-14 (America/New_York). The real monitoring, external restart and Admin browser gates passed. Signed publication and remote CI verification follow this local checkpoint; milestones 6–9 remain required.

## Resulting behavior

Persistent SQLite-backed schedules, fenced operation leases and durable recovery coordinate CLI/API/scheduled operations. Identical inputs retain actual human false-positive memory. A party hash change reopens the pairing with the original actor, note and real field differences. Type-aware hash rule v2 and immutable historical v1 evidence remain unchanged from the user's explicit decision.

Auto-clear defaults off. Enabling requires an active Admin to type the exact acknowledgment, recorded permanently. Only future review observations strictly below the frozen integer slider receive system dispositions; equality stays open, deterministic likely matches stay queued, and slider changes never rewrite past outcomes. Conflicting matching thresholds require a valid joint update. The UI handles fractional matching bounds and refreshes monitoring/retention state after General settings change.

Encrypted SMTP settings and frozen encrypted outbox batches support morning reports, immediate likely alerts, invitation delivery, per-recipient retries and visible failure health. Both MIME alternatives include the exact ITA notice. A report advances its boundary only when every recipient accepts it. Retries preserve the original body, recipients and Message-ID; accepted recipients are not resent. Explicit server rejection is a definite failure; connection loss with an ambiguous acceptance outcome remains uncertain and requires explicit retry. Provider-side acceptance after an interrupted connection cannot guarantee exactly-once mail.

Authenticated PDF/CSV/ZIP exports and equivalent CLI commands preserve original comparisons, human identities, hashes, settings and complete run manifests. Immutable participation records preserve zero-hit screenings. Purged comparisons use actual permanent certificates rather than being reported as zero hits. PDFs package offline Unicode fonts and attach exact sanitized JSON; current-record sections are labeled. Current-view CSV reuses all filters across pagination, and the full ZIP contains every party CSV/JSON plus shared run/list/source/audit indexes and per-file checksums. Temporary artifacts close on success, cancellation and send failure.

Retention defaults to indefinite. Configured periods cannot be below five years. Only explicitly attested inactive bundles with known external event dates, sufficient age, no holds and no retained dependencies can be removed. New activity invalidates stale attestations, and a later attestation cannot lower an earlier known event horizon. Government holds require a written-authorization reference to release. A writer-locked eligibility check grants exact connection-local row deletion capabilities; ordinary SQL/ORM connections cannot enable them. Certificates and audit, source, party, revision and run provenance remain permanent. This is bounded comparison pruning, not erasure of audited customer information.

## Findings and limits

The final gate proves the original action's actor, note, hashes, audit group and suppression reference. The gate now verifies actual API/CSV equality and control inclusion before the report, then prior-control absence after the fixed boundary advances.

The gate5c runtime caught a real transport bug missed by the earlier mocked rejection test: Python SMTP exceptions inherit `OSError`, and the broad uncertain-delivery handler intercepted definite recipient rejection. The correction is verified against the actual local SMTP capture transport, including sender/DATA rejection and post-DATA disconnect/timeout, before a new untouched fixture gate. All earlier gate volumes are preserved; no evidence or credentials are reset to manufacture a pass.
