## Result and verified contracts

Admins configure one encrypted Entra application, add a tenant/environment source, discover accessible companies and explicitly select the company before a full import. Discovery alone does not bind or import; cached access can be cleared through its own native control. Company-bound source IDs and tenant/environment/company identities cannot be changed, deleted or replaced through ORM or raw SQL. Labels and health remain editable. Routing preserves the configured environment case; conservative case-folded uniqueness and UUID-only tenant acceptance are documented product restrictions.

The supported OAuth flow is application client credentials with the actual opaque access-token lifetime. Standard fixed Microsoft v2.0 APIs use `API.ReadWrite.All`, tenant consent and a restricted enabled BC application. No user redirect, refresh token or fabricated grant-revocation endpoint is introduced. This is a documented adjustment to the design's generic redirect wording. Actual restricted object permissions still require tenant validation.

Customer/vendor ingestion retains original fields and namespaced GUID identities. Posting restrictions never imply deletion. Strict pages, schemas, counts, origin/path, identities and byte limits validate both complete collections before business apply; `Prefer: odata.maxpagesize=300` does not cap the collection through `$top`. Unchanged hashes cause no party writes or new screening task. Type-only changes use hash rule v2 and re-screen only the changed party, preserving the original human decision and linking its actual recorded authority.

Incremental timestamps overlap by five minutes and save a poll-start cursor. A daily successful full reconciliation detects hard deletions; this is a product policy, not a retained CDC horizon. Deletion notifications request a complete poll and payload records never become party data. Fenced apply rechecks source/app generations, identity, token ownership and initiating Admin authority. Token, page, company and subscription HTTP run outside a SQLite writer. Authentication failure schedules retained subscription cleanup and requires reconnect; token reissuance is bounded.

Subscriptions retain their actual opaque IDs, ETags, expiry and encrypted client state. Create and renew use real anonymous POST challenges with a bounded sole-token response; outermost query scrubbing applies before routing and errors. Notifications authenticate every event outside the writer, then atomically commit a deduplicated receipt and durable poll after a short configuration recheck. Persistent 12-hour lifecycle jobs renew due subscriptions and retain cleanup failures. Pre-POST encrypted custody survives uncertain creates; trusted discovery prevents blind duplicate creation. Missing ETags, partial acceptance, renewal conflicts, original issuer offboarding, URL changes and a full cleanup backlog preserve retry material without granting party-mutation authority.

Disconnect stops polling immediately and preserves records, hits, snapshots, reviews and audit evidence. A remote cleanup failure remains visible and privately retryable, while the source is locally disconnected. Successful native retry removes the remote subscriptions and clears stored access. Entra consent remains under the tenant administrator's control.
