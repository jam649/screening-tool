## Verified contracts and privacy

Use one compatibility primitive `Adjudicator.noul(context: str, claim: str) -> float`; richer immutable evaluation metadata lives per invocation rather than mutable last-response fields. Jev's fixed current HTTPS endpoint is `https://api.typesafe.ai/v1/systemone`, with Bearer auth and named question map: state, requested model, questions.same_party.type=noul and instructions. Validate `answers.same_party.type`, numeric finite [0,1] `.noul`, returned model and actual usage. No separate Noul confidence or invented claim/probability transport field. Pin `jev-1.13.0` as verified at build time and record the actual returned identity; account entitlement and a real paid response remain untested.

Laya uses the same envelope and native `/v1/systemone`, with explicit multilingual checkpoint and 1024-token path. The benchmark's tokenizer sequence measured 35 overhead/989 state tokens; recompute for changed instructions/model/tokenizer. Apply ordered removal of remarks, then street addresses, then aliases beyond the best matching alternate. Preserve core identity evidence; fall back if it still does not fit. Hosted estimates must be labeled estimates, separately from response usage; no exact Jev tokenizer was verified. Avoid double retry owners and provider SDK body logging; sanitize errors before any run/audit/UI output.

Before a hosted key can be saved, the server must enforce the exact displayed acknowledgment: "Enabling Jev sends your customer and vendor names and addresses to TypeSafe AI for scoring. Laya keeps all data on this server." Keep write-only keys encrypted, omit them from public settings/exports and never echo entered values. Local deployment assumptions must be enforced: an arbitrary remote URL cannot support the Laya privacy statement. Explicit connection tests are bounded and return public facts/failure codes. Invalid keys, unauthorized/invalid schemas and oversized state fall back honestly; transient retry budget and elapsed timeout are bounded.

## Matching and immutable evidence

Default `w_det=1`, `w_model=0` follows the actual held-out local quality evidence. Selecting an adapter can record probabilities without increasing its blend until calibration supports it. Deterministic generation/cutoff remain authoritative; remembered/completed human pairings bypass new adjudication. Only eligible deterministic comparisons at `review_threshold-10` or above call the adapter. Missing/invalid/unreachable model response gives `model_prob=null`, original deterministic confidence and a sanitized immutable run fallback; never turn failure into probability zero.

Blend and the deterministic likely-match rail must be enforced in the engine, independently of the adapter, so a high deterministic match is never demoted. Freeze provider/model/settings/actual usage/trimming/attempts/failure provenance before each Hit insert and in completed run evidence. Review the existing screening writer boundary before wiring remote calls: prepare immutable inputs and execute bounded inference outside a SQLite writer, then apply under the screening fence and current authority with original snapshot/hash provenance. Do not hold a long business write while waiting on a model, and do not silently reinterpret later source changes as the old comparison.

## Human training export and required gates

`screening-tool export training-pairs` uses original Hit snapshots and actual human `false_positive`/`confirmed_match` Dispositions. Include actor, immutable decision/hit/group/hash provenance. Exclude escalations, auto-clears, system list removals, zero-hit participation and suppressed repeats without a new human label. Preserve legitimate fanout labels with their actual recorded group rather than inventing new interactions. Purged comparison evidence is explicitly unavailable/omitted. No fine-tuning job is in v1.

Gate fixed-wire requests/strict response errors and finite probabilities, bounded transient retry/fallback, exact acknowledgment/role/CSRF/key redaction, fixed-order real-tokenizer truncation, likely rail under adversarial low model output, frozen old inputs/hashes under concurrent source change, original human-only export including fanout/purge omissions, real reachable local Laya probabilities and unreachable fallback through the normal runtime/CLI/browser. Preserve the existing Laya process and every prior fixture volume/key. Final complete suites, dependency audits, signed source publication and CI precede completion.
